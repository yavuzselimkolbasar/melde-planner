# ADR-0009: Native Android port in Kotlin + Jetpack Compose (Material 3)

## Context
The owner asked for Meldo on Android 16–17 with every feature and design the same as on iOS, except that Liquid Glass becomes Material You. Android can be built and tested on the owner's Windows machine (unlike iOS).

## Decision
- **Separate native app** in `apps/android` (Kotlin, Jetpack Compose, Material 3), `minSdk 36` (Android 16), `compileSdk`/`targetSdk 37` (Android 17). Gradle 9.8, AGP 9.3 with built-in Kotlin 2.4.
- **Same Rust core** through UniFFI's Kotlin bindings (JNA). `libmelde_ffi.so` is built with `cargo-ndk` (arm64-v8a, x86_64) and the bindings are generated by the pinned `tools/uniffi-bindgen`, both from Gradle tasks, so `./gradlew assemble…` builds everything. Bindgen reads the metadata from a host debug build because release `.so` files are stripped.
- **Same data model and JSON** (`data/Models.kt` mirrors `Shared/Models.swift`: field names, enum raw values, ISO-8601 dates, uppercase UUID strings), so a `data.json` reads on both platforms and later sync needs no mapping.
- **Same strings**: `L("German key", args)` looks up the iOS String Catalog, merged at build time into `assets/strings.json`; Android-only strings live in `apps/android/strings/*.json` with de/tr/en.
- **Platform equivalents**: widgets → Glance; Control Center control → Quick Settings tile; Live Activity → Android 16 Live Updates (promoted ongoing notification, ProgressStyle); App Intent → app shortcut; VisionKit scanner → ML Kit Document Scanner (Google Play services); Keychain → Android Keystore (AES-GCM); `ASWebAuthenticationSession` → Custom Tabs; WKWebView SSO login → WebView + CookieManager; BGAppRefresh → WorkManager; alternate icons → activity aliases (with a monochrome layer for themed icons); iPad sidebar → permanent navigation drawer on screens ≥ 840 dp.
- **Material You**: Meldo orange stays the default accent (with Indigo and Grün); "Material You" (wallpaper colors via dynamic color) is an extra accent choice.
- Rust FFI change: `MeldeError` fields are named `detail` instead of `message`, because Kotlin exceptions already have `message`. Swift never read the field by name.

## Alternatives considered
- Kotlin Multiplatform / Compose Multiplatform sharing UI with iOS: would replace the SwiftUI app, which the spec requires to be native.
- A WebView/PWA wrapper: not native, no widgets/tile/Live Updates, and the PWA is a later phase.

## Consequences
- Two UI codebases to keep in step; the shared Rust core, data model and string catalog keep the behavior identical.
- The document scanner needs Google Play services (not available on de-Googled phones); PDF and photo import still work there.
- iOS Lock Screen accessory widgets have no Android phone equivalent.
- Sideloaded APKs are signed with the debug key until a release key and store listing exist.
